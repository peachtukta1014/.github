# addresses — where a document lives, and how to name it

Canonical home: `registry/docids.json` (curated) -> `registry/docmap.json` (GENERATED).

## The shape (verified 2026-11-21)
```json
{ "schema": "docids/v1",
  "ids": { "room.protocol": {"path": "30-System/ROOM_PROTOCOL.md"},
           "rule.priv":     {"path": "30-System/AGENT.md", "section": "RULE 4"} } }
```
- The **id is the documented form**; the **path is a value**. Never hardcode a path in prose when an id exists.
- One file may own two facts (`rule.shared` / `rule.priv` both -> `AGENT.md`) — that is legal.
- 15 ids registered; 379 broader doc entries appear in `bin/doc.py list` (tiers T0/T1/T2, budget, scope).

## Resolve
```
scripts/where <id>            # -> one path
bin/doc.py path <id>          # the underlying call
bin/doc.py get <topic> <sec>  # read a section
bin/doc.py list --tier T1     # browse by tier
```

## Regenerating the derived file — the trap
`registry/docmap.json` is GENERATED by `bin/gen_docmap.py`. **Without `--write` it only prints a
draft to stdout and still exits 0.** After any change to `docids.json`:
```
python3 bin/gen_docmap.py --write        # then CHECK THE MTIME, not the exit code
```

## Budgets
Each id carries `budget_lines`; `gen_docmap` reports `over_budget`. An id that stays OVER is
undecided work — shorten the entry line or raise the budget with a reason. Never leave it silent.
